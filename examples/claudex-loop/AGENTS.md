# Claudex Loop 실습 지침

설치된 `claudex-loop` 스킬을 사용한다. 현재 CLI 대화가 메인·계획자·구현자이며, 다른 CLI가 독립 검토자다.
`PLAN.md`에서 시작하는 `mode=review`로 진행한다. 계획 검토·수정·최종 검토는 각각 최대 2회다.

## 진행

1. 메인이 PLAN.md와 현재 코드를 읽고 계획을 확정한다. 필요한 계획 보완만 수행하고, 확정한 계획을 `01-plan.md`에 기록한다.
2. 다른 모델에 계획 검토를 요청한다. REVISE면 메인이 지적별 처리를 기록하고 계획을 보완한다. 같은 성공 결과를 `--resume`으로 이어받고 메인이 작성한 `--feedback`을 전달한다.
3. APPROVED 결과를 `check`로 확인한 뒤 메인이 직접 구현한다. 편집 대상은 `word_count.py`·`test_word_count.py`이며, 이미 정확한 코드는 유지한다. 구현 전 Git HEAD를 기록한다.
4. 메인이 `python3 -m unittest discover -s . -p 'test_*.py' -v`를 실행하고 실제 출력을 기록한다.
5. 구현자와 다른 모델의 새 세션에 `inspect --base <구현 전 HEAD>`로 최종 검토를 요청한다.
6. 필요한 수정은 메인이 수행하고 테스트를 다시 실행한다. 재검토도 새 세션을 사용한다. 실패·차단·미해결 지적은 남기고 종료하며, 커밋·푸시는 하지 않는다.

## 검토 호출

이 폴더에서 `python3 review_runner.py`를 사용한다. 원본 스킬 runner를 가져오되, 하위 폴더 Git 경로와 검토 CLI 설정만 보정한다.
`--repo . --plan PLAN.md`와 실제 `--host`·`--builder`를 전달한다. 루프는 메인 대화가 진행한다.

Codex 검토자는 읽기 전용이며 플러그인·앱·훅·발견된 MCP를 비활성화한다. 개인 config에서는 모델·추론 수준 기본값만 전달한다.
Claude 검토자는 safe mode·빈 strict MCP 설정·읽기 전용 도구를 사용한다. 개인 플러그인을 전역에서 끄도록 요청할 필요가 없다.

## 기록

`output/cli-claude/<새 실행 ID>/` 또는 `output/cli-codex/<새 실행 ID>/`에 다음 파일을 만든다.

- `01-plan.md`: 메인이 확정한 계획
- `02-plan-review-01.md`: 검토 응답 전문·지적별 처리·원본 위치
- `03-implementation-01.md`: 변경 파일·설명·테스트 명령·실제 출력
- `04-final-review-01.md`: 최종 검토 응답 전문·지적별 처리·원본 위치
- `05-summary.md`: 최종 판정·남은 문제·각 기록 위치

회차가 늘면 번호가 다른 파일을 추가한다. 기록마다 담당 CLI·확인 가능한 모델·시각을 적는다.
응답 전문과 요약을 구분하고, 내부 추론이나 저장되지 않은 과거 응답은 만들지 않는다.
원본 runner 기록은 기본 고유 `/tmp/claudex-*` 경로에 보존한다. 과거 output은 현재 성공의 근거로 사용하지 않는다.
output은 검토 스냅샷에서 제외되므로 최종 검토 후에도 해당 실행의 결과를 기록할 수 있다.
